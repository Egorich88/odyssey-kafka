# Страница «Обзор»

Главная мониторинговая страница Odyssey

## Структура

- **Состояние кластера** — сводные KPI и таблица брокеров с внутренней прокруткой.
- **Сертификаты Kafka** — табличный список сертификатов и сроков действия.
- **Пропускная способность кластера** — входящий и исходящий поток сообщений.
- **Пропускная способность по топикам** — график, текущее и максимальное значение каждого активного топика.
- **Группы потребителей** — график лага и таблица групп с внутренней прокруткой.
- **Последние события** — события Kafka с фильтром уровня и внутренней прокруткой.

## Поведение

- При смене кластера старые данные не используются для нового bootstrap.
- Автообновление данных не меняет состояние доступности кластера.
- Доступность Kafka контролируется на уровне общего Layout.
- Настройки и Пользователь доступны независимо от состояния Kafka-кластера.
- Увеличение панели открывает её в центрированном модальном режиме с размытым фоном.

## Стили

Все стили страницы находятся в `src/pages/overview/styles/` и используют CSS-переменные тем KSC.


## Переработка компоновки (2026-11-01)

- `Overview.tsx` — четыре адаптивных ряда: сводка кластера на всю ширину; брокеры и сертификаты; пропускная способность и топики; lag и события.
- `ClusterHealthPanel.tsx` — только верхняя сводка с отдельным индикатором статуса кластера.
- `BrokersPanel.tsx` — отдельная таблица брокеров, использующая данные `/api/overview/health`.
- `cluster-health-panel.css` — адаптивное расположение сводки и оформление ячеистой шкалы CPU.
- `overview.css` — новая сетка с увеличенной долей ширины для пропускной способности.
- `CertificatesPanel.tsx` — короткое название «Сертификаты».
- `EventsPanel.tsx` — короткое название «События».

Важно: поле `cpu` в текущем backend вычисляется из `docker stats` для контейнера Kafka и записывается в каждый объект брокера. Это реальная метрика контейнера, но не индивидуальная загрузка CPU каждого брокерного процесса. Для персональной нагрузки по каждому брокеру потребуется отдельный источник метрик на стороне Kafka/JMX/Prometheus или метрики контейнеров по отдельности.


## Корректировка дашборда (2026-11-01)

- У панели «Состояние кластера» убран заголовок, информационная подсказка и кнопка увеличения: верхняя строка сразу показывает статус и KPI. Высота строки уменьшена с 20% до 14% доступной высоты дашборда (снижение на 30%).
- Исправлен цикл повторной загрузки `/api/overview/health`: callback передачи данных в родительскую страницу теперь стабилен через `useCallback`. Ранее inline-функция менялась при каждом рендере, повторно запускала `useEffect` панели, что могло приводить к кратковременному появлению и исчезновению данных.
- Цвета статусов: зелёный — `healthy`; оранжевый — `warning`; красный — `critical`; нейтральный — `unknown`. Критический статус обоснован недоступным брокером, ошибкой контроллера, партицией без лидера или Dead consumer group. Недоступность кластера до получения ответа API не маскируется под критический статус этой панели: в таком случае данные остаются неизвестными, а общий экран недоступного кластера обрабатывается уровнем Layout.
- Панели «Брокеры» и «Сертификаты» теперь делят строку поровну (50/50).
- Ширина «Пропускная способность кластера» уменьшена с 62,5% до 37,5%; «Пропускная способность по топикам» увеличена с 37,5% до 62,5%.
- Шкала нагрузки брокеров заменена на спокойный градиент: зелёный для низкой, жёлтый для повышенной и красный для высокой нагрузки. Убрана движущаяся ячеистая текстура, оставлена плавная анимация изменения значения.

Примечание: текущая backend-метрика CPU является метрикой контейнера Kafka и может повторяться у всех брокеров. Она не является индивидуальной загрузкой каждого брокера.
