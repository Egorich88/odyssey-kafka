# Docker: владелец, HTTPS и сохранность профилей

В v4.3.2 backend требует созданного локально владельца. Прежняя схема
HTTP Nginx → backend на адресе контейнера несовместима с проверкой транспорта
серверной сессии. Новая схема: браузер → **HTTPS Nginx → проверяемый TLS Go**.
Forwarded-заголовки не служат доказательством безопасного транспорта.

## Первый запуск

Ниже приведены команды для нового Docker-развёртывания, а не для переключения
уже работающего Odyssey. Сначала сохраните текущие данные и резервную копию
браузерного профиля. Не удаляйте старый localStorage до подтверждённого переноса.

1. Настройте несекретные переменные окружения. Значения сети и портов возьмите
   из фактического разрешённого профиля; пустая политика запрещает Kafka-адреса.
   Разрешить нужно bootstrap **и advertised endpoints**.

   PowerShell:

   ```powershell
   $env:ODYSSEY_PUBLIC_HOST = 'localhost'
   $env:ODYSSEY_HTTPS_PORT = '8443'
   $env:ODYSSEY_PUBLIC_ORIGIN = 'https://localhost:8443'
   $env:ODYSSEY_KAFKA_ALLOWED_NETWORKS = '192.0.2.0/24' # Замените тестовый диапазон своим разрешённым.
   $env:ODYSSEY_KAFKA_ALLOWED_PORTS = '9092' # Только реально используемые порты.
   ```

   Bash/WSL:

   ```bash
   export ODYSSEY_PUBLIC_HOST=localhost ODYSSEY_HTTPS_PORT=8443
   export ODYSSEY_PUBLIC_ORIGIN=https://localhost:8443
   export ODYSSEY_KAFKA_ALLOWED_NETWORKS=192.0.2.0/24 ODYSSEY_KAFKA_ALLOWED_PORTS=9092
   ```

   Это примеры без реальных секретов. Для внешнего имени укажите его одновременно
   в `ODYSSEY_PUBLIC_HOST` и `ODYSSEY_PUBLIC_ORIGIN`. Origin включает схему и порт,
   без завершающего `/`. По умолчанию HTTPS доступен только на `127.0.0.1`.

2. Проверьте и соберите конфигурацию:

   ```console
   docker compose config --quiet
   docker compose build backend-service frontend-service tls-init
   docker compose run --rm owner-storage-init
   docker compose --profile setup run --rm owner-init
   ```

   Последняя команда запрашивает пароль интерактивно без эха. Не передавайте
   настоящий пароль аргументом, через переменную окружения или shell history.
   Повторная регистрация владельца запрещена; существующие данные не заменяются.

3. Подготовьте сертификаты:

   ```console
   docker compose run --rm tls-init
   docker compose run --rm --no-deps --entrypoint cat tls-init /state/ca/ca.crt
   ```

   Последняя команда выводит **только публичный сертификат CA**. Доверие этому CA
   на клиентском компьютере настройте вручную, проверив источник сертификата.
   Не отключайте проверку сертификата и не используйте обход предупреждения
   браузера как постоянную процедуру. Для организации можно подготовить в этих
   томах сертификаты доверенной CA с нужными SAN и владельцами файлов.

4. Запустите Odyssey после подготовки доверия:

   ```console
   docker compose up -d frontend-service
   ```

   Откройте `https://localhost:8443`, войдите владельцем. Сервисы подготовки
   завершаются до старта backend; frontend ждёт его TLS healthcheck.
   Backend не публикует порт 8080 на хосте. Тестовый Kafka запускается только
   с отдельным профилем `local-kafka` и не является частью обычного запуска.

## Приватные тома и перезапуск

| Том | Содержимое | Доступ работающего приложения |
|---|---|---|
| `owner-data` | Зашифрованное хранилище владельца и профилей | backend RW |
| `owner-key` | Отдельный ключ шифрования | backend RO |
| `tls-ca` | Ключ и сертификат локальной CA | только init |
| `backend-tls` | TLS-ключ, сертификат backend и публичная CA | backend RO |
| `frontend-tls` | TLS-ключ, сертификат frontend и публичная CA | Nginx RO |

Каталоги имеют права `0700`, приватные ключи — `0600`. Контейнеры приложения
работают без root и capabilities, с read-only корневой файловой системой.
Init не исправляет небезопасные права непустого хранилища автоматически.
Частично созданный набор TLS, чужой ключ, изменение hostname или сертификат,
истекающий менее чем через сутки, останавливают подготовку; автоматической
ротации с потерей доверия нет. Сертификаты leaf выдаются на 365 дней:
ротацию и обновление доверия нужно подготовить заранее.

`docker compose restart backend-service` сохраняет владельца и профили,
но завершает серверные сессии: после перезапуска нужно войти повторно.
Не запускайте несколько backend-процессов с одним хранилищем.
Резервируйте `owner-data` и `owner-key` раздельно и согласованно, при закрытом
хранилище. Потеря ключа делает данные невосстановимыми. Не выполняйте
`docker compose down -v` для рабочего проекта, не копируйте тома в Git/образы.

## Миграция браузерных настроек

Хранилище браузера изолировано по origin. Страница `https://localhost:8443`
не увидит профили из `http://localhost:5173` автоматически. Сначала выполните
переход на версию с владельцем **на прежнем origin** согласно
[инструкции миграции](security-owner-migration.md), а затем переносите
согласованную резервную копию серверного хранилища и ключа в Docker.
Не экспортируйте секреты в чат или URL. Прямой импорт из другого origin
данной доработкой не добавлен.

Ошибка одной записи (валидация, серверная политика адресов, временно
отключённый GSSAPI, конфликт миграции) больше не блокирует обработку остальных.
Успешно сохранённые профили доступны для выбора. Исходный список остаётся
без изменений до успешного переноса всех записей; повтор идемпотентен.
До завершения всего переноса редактирование/удаление серверных записей через
этот интерфейс остаётся закрытым, чтобы старый список не перезаписал изменения.
При потере сессии, сети, 429 или 5xx отправка прекращается. Ошибочную запись
следует восстановить по резервной копии; автоматического удаления нет.

## Проверки перед релизом

Без Docker Engine, в Linux/WSL с OpenSSL:

```console
python3 -B -m unittest discover -s docker -p test_init.py -v
cd backend
go test ./...
go test -race ./...
go vet ./...
go build ./...
```

При отдельно разрешённом работающем Docker Engine:

```console
node docker/smoke.mjs --run
```

Smoke-тест использует уникальный проект `odyssey-smoke-<UUID>`, свободный порт,
новые тома, сгенерированный в памяти тестовый пароль и синтетический профиль.
Он проверяет HTTPS, повторный owner-init, сессию и сохранение профиля после
restart, затем удаляет **только собственный** тестовый проект и его тома.
Kafka не запускается; профиль регистрируется без Kafka-подключения.
Без `--run` контейнеры не запускаются.
