# Odyssey v4.3.2 — заметки к подготовке релиза

Релизная доработка устраняет несовместимость Docker Compose с авторизацией
единственного владельца установки. Данные владельца и Kafka-профили сохраняются
в зашифрованном серверном хранилище; отдельный ключ расположен в приватном томе.
Первичная регистрация выполняется локальной интерактивной командой owner-init.

Nginx обслуживает HTTPS и соединяется с backend через TLS с проверкой CA
и имени backend-service. Secure/HttpOnly/SameSite cookie и проверки Origin/CSRF
сохранены. Авторизация через доверие к Forwarded-заголовкам не добавлена.
Обычный запуск Compose не запускает тестовую Kafka автоматически.

Перенос legacy-профилей продолжает обработку после отказа отдельной записи.
Исходный список остаётся в браузере для восстановления, пока не перенесены
все записи. Уже перенесённые подключения доступны; секреты не добавляются
в ответы API, сообщения об ошибках или новое браузерное хранилище.

Ограничения:

- GSSAPI временно недоступен: библиотечные DNS/TCP/UDP-переходы нельзя считать
  надёжно ограниченными одной только проверкой bootstrap. Fallback на PLAINTEXT нет.
- Хранилище предназначено для одного backend-процесса.
- Изменение browser origin не переносит localStorage. Переход на Docker HTTPS
  требует предварительной миграции на прежнем origin и резервной копии.
- Docker-сертификаты требуют клиентского доверия и плановой ротации.
- До выпуска обязательны контейнерный smoke-тест и проверки уже разрешённых
  тестовых Kafka-профилей. Сборка сама по себе не подтверждает эти сценарии.
